# runpodTools

A modular, idempotent bootstrap system for provisioning AI workloads on RunPod instances. Runs locally and orchestrates remote setup via SSH using numbered steps.

## Architecture

### Key Concepts

| Concept           | Description                                    |
|-------------------|------------------------------------------------|
| Local control     | Scripts run from your local machine            |
| Remote execution  | Commands run on the pod via SSH                |
| Step system       | Modular numbered scripts (`10_`, `20_`, etc.)  |
| Feature flags     | Enable/disable steps dynamically               |
| Shared utilities  | `common.sh`, `ssh.sh`, logging helpers         |

### Directory Structure

```
runpodTools/
  lib/                      # Reusable library functions
    common.sh               # Logging, run, die, timestamp helpers
    ssh.sh                  # SSH command builders, remote execution
    apt.sh                  # APT package management
    conda.sh                # Conda environment setup
    git.sh                  # Git repository management (idempotent)
    llava.sh                # LLaVA install helpers
    run.sh                  # Remote run helpers
    workspace.sh            # Common paths, state tracking
    diagnostics.sh          # System diagnostics
  steps/                    # Individual setup steps
    05_startup.sh           # Startup / environment checks
    10_diagnostics.sh       # System diagnostics
    20_base_tools.sh        # Base system tools via apt
    30_conda.sh             # Miniconda setup
    40_comfyui.sh           # ComfyUI setup
    50_kohya.sh             # Kohya SS setup
    60_upload_models.sh     # Model upload instructions
    65_video_upscale.sh     # Video upscaling setup
    70_llava.sh             # LLaVA setup
    75_llava_adapter.sh     # LLaVA adapter setup
  test/
    createFakePod.sh        # Local pod simulation for testing
  documentation/            # Reference docs
  logs/                     # Bootstrap logs (auto-created)
  runpodBootstrap.sh        # Remote-side step runner
  createPod.sh              # Create a new RunPod instance
  testLlavaInstall.sh       # Verify LLaVA installation
  help.md                   # Quick reference
  state.env                 # Completed step tracking
```

The following scripts are **generated** at runtime into the local working directory or uploaded to the pod:

| Script              | Generated by          | Location      | Purpose                                 |
|---------------------|-----------------------|---------------|-----------------------------------------|
| `comfyStart.sh`     | `40_comfyui.sh`       | pod workspace | Start ComfyUI in tmux                   |
| `uploadModels.sh`   | `60_upload_models.sh` | local         | Upload models and workflows to the pod  |
| `videoUpscale.sh`   | `65_video_upscale.sh` | pod workspace | Run Real-ESRGAN upscaling pipeline      |
| `llavaStart.sh`     | `70_llava.sh`         | pod workspace | Start the LLaVA API server              |
| `adapterStart.sh`   | `75_llava_adapter.sh` | pod workspace | Start the LLaVA adapter                 |

### Runpod Filesystem Layout

| Path                      | Purpose               |
|---------------------------|-----------------------|
| `/workspace`              | Working directory     |
| `/workspace/ai-tools`     | Installed tools       |
| `/workspace/video-input`  | Video upscale inputs  |
| `/workspace/video-output` | Video upscale outputs |

## Usage

### Quick Start

```bash
# Basic setup with ComfyUI (default)
./runpodTools/runpodFromSSH.sh ssh root@HOST -p PORT -i ~/.ssh/id_ed25519

# With Kohya
./runpodTools/runpodFromSSH.sh --kohya ssh root@HOST -p PORT -i ~/.ssh/id_ed25519

# With all features
./runpodTools/runpodFromSSH.sh --comfyui --llava --upscale ssh root@HOST -p PORT -i ~/.ssh/id_ed25519

# Dry run to see what would happen
./runpodTools/runpodFromSSH.sh --dry-run ssh root@HOST -p PORT -i ~/.ssh/id_ed25519
```

### Feature Flags

| Flag        | Description                    |
|-------------|--------------------------------|
| `--comfyui` | Install ComfyUI                |
| `--kohya`   | Install Kohya                  |
| `--llava`   | Install LLaVA                  |
| `--upscale` | Install video upscaling tools  |

### Advanced Usage

```bash
# List available steps
./runpodFromSSH.sh --list ssh root@HOST -p PORT -i KEY

# Run only a specific step
./runpodFromSSH.sh --only 40_comfyui ssh root@HOST -p PORT -i KEY

# Start from a specific step
./runpodFromSSH.sh --from 30_conda ssh root@HOST -p PORT -i KEY

# Skip a step
./runpodFromSSH.sh --skip 20_base_tools ssh root@HOST -p PORT -i KEY

# Force rerun (ignore state file)
./runpodFromSSH.sh --force ssh root@HOST -p PORT -i KEY

# Copy scripts only, don't run
./runpodFromSSH.sh --no-run ssh root@HOST -p PORT -i KEY
```

### Direct Remote Execution

If you're already on the RunPod instance:

```bash
# Run all steps
bash /workspace/runpodTools/runpodBootstrap.sh

# With options
bash /workspace/runpodTools/runpodBootstrap.sh --kohya --force

# List steps
bash /workspace/runpodTools/runpodBootstrap.sh --list

# Run specific step
bash /workspace/runpodTools/runpodBootstrap.sh --only 40_comfyui
```

## Features

### Idempotent by Design

Each step checks if work is already done:
- If desired state exists → skip
- If exists but wrong → repair or move aside
- State tracked in `/workspace/runpodTools/state.env`
- Use `--force` to ignore state and rerun

### Smart Logging

- All output tee'd to `/workspace/runpodTools/logs/bootstrap.TIMESTAMP.log`
- Survives disconnects
- Easy debugging

Log conventions:

| Output           | Meaning                |
|------------------|------------------------|
| `...message`     | Progress / in-progress |
| `message...`     | Complete               |
| `ERROR: message` | Failure                |

### Modular Steps

Each step is independent and can be:
- Run individually (`--only`)
- Skipped (`--skip`)
- Started from (`--from`)
- Listed (`--list`)

### Safe Remote Operations

- Idempotent git clones (auto-pull if exists)
- Moves aside conflicting directories with timestamps
- Non-interactive apt (no hangs)
- Conda channel resilience

## Video Upscaling

Uses Real-ESRGAN directly (not Video2X).

### Installed paths

```
/workspace/ai-tools/realesrgan/
/workspace/video-input/
/workspace/video-output/
```

### Usage on pod

```bash
/workspace/videoUpscale.sh input.mp4 output.mp4 2
```

| Argument | Description       |
|----------|-------------------|
| input    | Input video path  |
| output   | Output video path |
| scale    | `2` or `4`        |

### Pipeline

```
video → ffmpeg extract frames → Real-ESRGAN upscale → ffmpeg reassemble
```

### Workflow

1. Bootstrap with `--upscale`:
   ```bash
   ./runpodFromSSH.sh --upscale ssh root@HOST -p PORT -i KEY
   ```
2. Upload input:
   ```bash
   scp input.mp4 root@HOST:/workspace/video-input/
   ```
3. Run upscale:
   ```bash
   /workspace/videoUpscale.sh input.mp4 output.mp4 2
   ```
4. Download result.

## State File

Located at `/workspace/runpodTools/state.env`, tracks completed steps:

```bash
DONE_DIAGNOSTICS=1
DONE_BASE_TOOLS=1
DONE_CONDA=1
DONE_COMFYUI=1
```

Delete to force rerun all steps, or use `--force` flag.

## Development

### Adding a New Step

1. Create `steps/XX_stepname.sh`:

```bash
#!/usr/env bash
set -euo pipefail

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
LIB_DIR="$(dirname "$SCRIPT_DIR")/lib"

source "$LIB_DIR/common.sh"
source "$LIB_DIR/workspace.sh"

main() {
  log "step: stepname"

  if isStepDone "STEPNAME" && [[ "${FORCE:-0}" != "1" ]]; then
    log "already done"
    return 0
  fi

  # Guard for optional feature flags:
  # [[ "${ENABLE_FEATURE:-0}" != "1" ]] && return 0

  # Do work here

  markStepDone "STEPNAME"
  log "done"
}

if [[ "${BASH_SOURCE[0]}" == "$0" ]]; then
  main "$@"
fi
```

2. Add to `ALL_STEPS` array in `runpodBootstrap.sh`
3. Document in `--list` output

### Adding a New Library Function

1. Add to appropriate `lib/*.sh` file
2. Keep functions idempotent where possible
3. Use `run` wrapper for dry-run support
4. Use `log`/`warn`/`error` for output

## Troubleshooting

### Check logs

```bash
ls -lrt /workspace/runpodTools/logs/
tail -f /workspace/runpodTools/logs/bootstrap.LATEST.log
```

### Check state

```bash
cat /workspace/runpodTools/state.env
```

### Reset state

```bash
rm /workspace/runpodTools/state.env
```

### Dry run

```bash
./runpodFromSSH.sh --dry-run ssh root@HOST -p PORT -i KEY
```

This shows all commands that would be executed without actually running them.
